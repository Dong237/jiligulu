# Feature Specification: 叽里咕噜 MVP（JiLiGuLu MVP）

**Feature Branch**: `001-jiligulu-mvp`
**Created**: 2026-03-06
**Status**: Draft
**Input**: 叽里咕噜MVP — 面向55-70岁中国退休人群的AI英语学习伴侣App

## User Scenarios & Testing

### User Story 1 - 老人语音对话学英语 (Priority: P0)

退休阿姨打开App，看到AI小鹦鹉"叽叽"在打招呼，点击"开始聊天"大按钮，进入语音对话。叽叽用中文为主带入英语关键词（如"I'd like some apples"），引导阿姨跟读。阿姨说错了不会被批评，而是收到"差一点点！再试一次？"的鼓励。每次对话5-8分钟，学3-5个实用短语。

**Why this priority**: 这是产品核心价值——语音对话学英语是叽里咕噜存在的根本原因。没有这个功能，产品不成立。

**Independent Test**: 用户打开App → 点击开始聊天 → 与叽叽完成一次完整语音对话 → 学会至少1个英语表达 → 对话结束看到学习总结。

**Acceptance Scenarios**:

1. **Given** 用户首次打开App且已通过子女设置完成登录, **When** 用户点击"开始聊天"按钮, **Then** 进入语音对话页，叽叽用中文打招呼并引导开始第一个场景对话
2. **Given** 用户在语音对话中, **When** 用户按住说话按钮说出英语尝试（即使发音不标准）, **Then** 叽叽先给予正面肯定（"说得很好！"/"很接近了！"），再温和引导改进
3. **Given** 语音对话进行中, **When** 用户完成5-8分钟对话或主动结束, **Then** 系统显示学习总结（本次学了几个新表达）并生成复习卡片
4. **Given** 用户说话后, **When** 系统处理语音, **Then** 端到端延迟（用户说完到听到叽叽回复）不超过2秒
5. **Given** ASR无法识别用户语音, **When** 识别失败, **Then** 叽叽播放兜底语音"叽叽没听清，阿姨再说一遍？"而非显示技术错误信息

---

### User Story 2 - 场景教学系统 (Priority: P0)

用户可以在预设的生活场景中学习英语。MVP提供10个场景（5个免费入门 + 5个会员日常场景），每个场景包含3-5个核心短语。场景Prompt驱动对话内容，确保教学聚焦。

**Why this priority**: 场景是对话的内容基础。没有场景，对话就没有结构化教学目标。

**Independent Test**: 用户选择"买水果"场景 → 叽叽引导用户在水果摊情境中学习"I'd like some apples""How much?""Here you go" → 对话结束时用户掌握这3个表达。

**Acceptance Scenarios**:

1. **Given** 用户在首页或场景列表, **When** 用户选择一个场景, **Then** 进入该场景的对话，叽叽用中文描述场景背景并引出第一个英语表达
2. **Given** 免费用户, **When** 浏览场景列表, **Then** 可看到5个入门场景为可用状态，5个日常场景标注为会员内容
3. **Given** 用户完成一个场景, **When** 下次进入对话, **Then** 系统推荐下一个合适的场景（按学习路径）

---

### User Story 3 - 适老化主界面 (Priority: P0)

首页只有鹦鹉动画和一个"开始聊天"大按钮。全App最小字号18sp，正文22sp+。按钮触控区 ≥ 48x48dp。暖色调配色。永远不显示红色错误标记或负面分数。底部导航最多3个Tab。

**Why this priority**: 目标用户是55-70岁退休人群。如果界面不够简洁易用，用户根本无法使用产品，其他功能全部白费。

**Independent Test**: 邀请3位55-70岁无技术背景老人，在无人指导下打开App并完成一次对话。成功率需 ≥ 80%。

**Acceptance Scenarios**:

1. **Given** 用户打开App, **When** 首页加载完成, **Then** 屏幕上只有鹦鹉动画区域和一个"开始聊天"大按钮，加载时间 < 1秒
2. **Given** 任何页面, **When** 查看所有文字元素, **Then** 最小字号 ≥ 18sp，正文 ≥ 22sp
3. **Given** 任何页面, **When** 查看所有可点击元素, **Then** 触控区域 ≥ 48x48dp
4. **Given** 用户操作出错或网络异常, **When** 需要提示用户, **Then** 使用暖色提示（柔橙#F5A623），不使用红色，不显示技术错误信息

---

### User Story 4 - 子女设置流 (Priority: P0)

子女下载App，手机号注册，填写父母信息（称呼/性别/学习动机），选择学习目标，系统生成二维码。父母用手机扫码即可自动登录，无需注册。全流程3分钟内完成。

**Why this priority**: 老人无法自行完成注册和配置。子女设置是老人能用上产品的前提。

**Independent Test**: 子女从零开始注册 → 填信息 → 生成二维码 → 父母扫码 → 父母端自动登录 → 叽叽打招呼。全程 ≤ 3分钟。

**Acceptance Scenarios**:

1. **Given** 子女首次打开App, **When** 选择"帮爸妈设置", **Then** 进入设置向导：注册 → 填父母信息 → 选目标 → 生成二维码
2. **Given** 子女完成设置并生成二维码, **When** 父母用手机摄像头扫描二维码, **Then** 父母手机自动打开App并登录，直接看到叽叽打招呼
3. **Given** 设置流程中, **When** 网络中断, **Then** 已填信息自动保存，恢复网络后可继续

---

### User Story 5 - 子女仪表盘 (Priority: P0)

子女在App中通过密码切换到子女端，查看父母学习进展：本周学了几次、多少分钟、几个新词、连续天数、叽叽成长状态。可一键生成分享卡片发到微信朋友圈/家族群。

**Why this priority**: 子女是付费决策者。"看到爸妈真的在用"是付费和续费的核心驱动力。周报推送让子女持续关注。

**Independent Test**: 子女切换到子女端 → 看到父母本周学习数据 → 点击分享 → 生成微信分享卡片。

**Acceptance Scenarios**:

1. **Given** 用户在"叽叽"Tab, **When** 点击"家人"入口并输入4位密码, **Then** 进入子女仪表盘，显示父母本周学习概览
2. **Given** 子女在仪表盘, **When** 点击"一键分享", **Then** 生成带鹦鹉IP的精美分享卡片，可分享到微信
3. **Given** 父母完成一周学习, **When** 周日晚8点, **Then** 子女收到推送"妈妈这周学了X个新词！"

---

### User Story 6 - 复习卡片 (Priority: P0)

每次对话结束自动生成复习卡片，包含本次学的核心短语 + 中文释义 + 简化音标 + 中文谐音。卡片可点击听发音，可一键分享到微信。

**Why this priority**: 复习卡片解决"学了就忘"的核心痛点，同时是社交裂变的关键载体。

**Independent Test**: 完成一次对话 → 自动看到复习卡片 → 卡片上有英文/中文/音标/谐音 → 点击可听发音 → 可分享到微信。

**Acceptance Scenarios**:

1. **Given** 用户完成一次语音对话, **When** 对话结束, **Then** 自动显示复习卡片，包含本次学习的所有核心短语
2. **Given** 复习卡片显示中, **When** 用户点击某个短语旁的喇叭图标, **Then** 播放该短语的标准发音
3. **Given** 复习卡片显示中, **When** 用户点击"分享到微信", **Then** 生成带鹦鹉IP和二维码的分享图片并调起微信分享

---

### User Story 7 - 鹦鹉基础动画 (Priority: P0)

叽叽有7个基本动画状态：睡觉（App待机）、醒来（用户进入）、教学（对话中）、开心（用户说对了）、鼓励（用户说错了）、思考（AI处理中）、再见（对话结束）。动画状态随对话进展自动切换。

**Why this priority**: 鹦鹉是产品的灵魂。没有动画，叽叽只是一个语音机器人，无法建立情感连接。

**Independent Test**: 打开App看到叽叽睡觉 → 进入看到醒来动画 → 对话中看到教学表情 → 回答正确看到开心跳跃 → 对话结束看到挥翅膀再见。

**Acceptance Scenarios**:

1. **Given** App在首页待机, **When** 用户打开App, **Then** 叽叽从睡觉状态切换到醒来动画（睁眼+伸懒腰+扑翅膀）
2. **Given** 语音对话进行中, **When** 用户回答正确, **Then** 叽叽播放开心动画（跳起来+翅膀拍拍）
3. **Given** 语音对话进行中, **When** AI正在处理回复, **Then** 叽叽播放思考动画（歪头+眨眼），而非显示loading图标

---

### User Story 8 - 间隔重复(SRS) (Priority: P1)

基于改良SM-2算法（老年人版，间隔比标准更短），系统自动安排已学词汇的复习时间，在新场景对话中自然复现旧词汇，不让用户感觉在"做复习题"。

**Why this priority**: 解决老年用户"学了就忘"的核心痛点。SRS是留存的技术基础。

**Independent Test**: 用户3天前学了"Hello" → 今天进入"买水果"场景 → 叽叽在开场时自然说"进店先跟老板打个招呼，还记得怎么说吗？Hello！"

**Acceptance Scenarios**:

1. **Given** 用户学过某个短语已到复习时间, **When** 用户开始新场景对话, **Then** 叽叽在对话中自然带出该短语（不是生硬的"复习时间到了"）
2. **Given** 用户成功复习某短语, **When** 复习完成, **Then** 该短语的下次复习间隔根据SRS算法延长
3. **Given** 用户未能回忆起某短语, **When** 需要提示, **Then** 不重置到最初等级（避免挫败感），而是降一级并缩短间隔

---

### User Story 9 - 鹦鹉成长系统 (Priority: P1)

叽叽有6个成长阶段（蛋蛋期 → 毛球期 → 雏鸟期 → 学飞期 → 彩羽期 → 歌唱期），由学习行为驱动XP积累。完成对话、学新短语、连续打卡都能获得XP。用户可以在"叽叽"Tab查看成长状态和里程碑。

**Why this priority**: 宠物成长可视化是长期留存的关键驱动力。"叽叽长出了小翅膀"比"你学了10个词"更有情感吸引力。

**Independent Test**: 用户连续学习3天 → 积累足够XP → 叽叽从"蛋蛋期"升级到"毛球期" → 用户看到升级动画和里程碑通知。

**Acceptance Scenarios**:

1. **Given** 用户完成一次对话, **When** 对话结束, **Then** 显示本次获得的XP及来源（如"完成对话+10XP，学了2个新短语+10XP"）
2. **Given** 叽叽XP达到下一阶段门槛, **When** XP足够, **Then** 播放成长进化动画，显示新阶段名称和描述
3. **Given** 用户在"叽叽"Tab, **When** 查看成长页面, **Then** 显示当前阶段、XP进度条、已达成里程碑列表

---

### User Story 10 - 每日主动邀约 (Priority: P1)

叽叽每天在用户常活跃的时间段发送一条推送，邀请用户来聊天。推送内容个性化（包含昨天学的内容）。每天最多1条，不做情感绑架。

**Why this priority**: 推送唤醒是习惯养成的关键手段，参考Duolingo"Lily Calls You"机制的成功经验。

**Independent Test**: 用户昨天学了"How much?" → 今天上午收到推送"叽叽想和你练练昨天学的 How much 呢！" → 点击推送 → 直接进入对话页。

**Acceptance Scenarios**:

1. **Given** 用户已设置推送权限, **When** 到达每日推送时间, **Then** 用户收到包含昨天学习内容的个性化推送
2. **Given** 用户点击推送, **When** App打开, **Then** 直接进入语音对话页（跳过首页），自动开始复习场景
3. **Given** 用户已连续3天未打开App, **When** 需要回流推送, **Then** 发送温暖但不绑架的推送，最多3次

---

### User Story 11 - 微信分享卡片 (Priority: P2)

带鹦鹉IP的精美分享图片，包含学习成果和产品二维码，可分享到微信朋友圈和家族群，是社交裂变的核心载体。

**Why this priority**: 分享卡片是增长飞轮的关键环节。子女分享"我妈今天和小鹦鹉聊了8分钟英语"引发其他子女好奇。

**Independent Test**: 子女在仪表盘点击分享 → 生成精美卡片（含学习数据+鹦鹉形象+二维码）→ 成功分享到微信。

**Acceptance Scenarios**:

1. **Given** 需要生成分享卡片, **When** 用户点击分享, **Then** 系统生成750x1334px的PNG图片，包含鹦鹉IP、学习数据、产品二维码
2. **Given** 分享卡片已生成, **When** 用户选择微信分享, **Then** 调起微信分享到朋友圈或指定聊天

---

### User Story 12 - 场景包购买/赠送 (Priority: P2)

子女可在子女仪表盘购买旅游/探亲场景包，作为礼物解锁给父母。支持微信支付/支付宝。

**Why this priority**: 场景包是变现的补充手段，同时"赠送"机制强化孝心经济定位。

**Independent Test**: 子女在场景管理页看到锁定的"出国旅游"包 → 点击购买 → 完成支付 → 父母端该场景包自动解锁。

**Acceptance Scenarios**:

1. **Given** 子女在场景管理页, **When** 点击被锁定的场景包, **Then** 显示该场景包的内容介绍和购买/赠送选项
2. **Given** 子女完成支付, **When** 支付成功, **Then** 父母端该场景包立即解锁，父母下次打开场景列表可见

---

### Edge Cases

- 用户说了很长时间但全是中文没有英语，叽叽如何引导？→ 温和提示"阿姨来试试说英语？就一个词就行"
- 网络中断导致对话中断？→ 友好提示"叽叽休息了"，本次对话进度自动保存
- 用户发音完全无法识别（ASR返回空）？→ 叽叽播放"没听清，再说一遍？"，连续3次失败后建议使用快捷回复按钮
- 老人误触进入子女端？→ 需要4位密码，输错提示"这是家人管理的入口哦"
- 用户在免费试用期结束时正在对话？→ 不打断当前对话，结束后提示付费
- LLM生成了不当内容？→ 内容安全过滤层拦截，替换为安全兜底回复
- 用户聊到非英语话题（健康/政治/孤独）？→ 按话题类型温和引导回英语学习

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 提供基于WebSocket的实时语音对话功能，支持用户语音输入和AI语音+文字输出
- **FR-002**: 语音管线 MUST 采用流式级联架构：VAD(端上) → ASR → LLM → TTS → 播放+字幕同步
- **FR-003**: ASR MUST 支持中英混合语音识别，并采用宽容模式（VAD静音阈值2.5秒、高发音容忍度）
- **FR-004**: LLM对话 MUST 遵循70/30中英语言比例（初学者可调至90/10），每轮最多教3个新表达
- **FR-005**: 每次AI反馈 MUST 先给予正面肯定，再温和引导改进。禁止使用"错了""不对"等负面词汇
- **FR-006**: 系统 MUST 提供10个预设场景（5免费+5会员），每场景3-5个核心短语
- **FR-007**: 首页 MUST 只显示鹦鹉动画和一个"开始聊天"按钮，底部导航最多3个Tab
- **FR-008**: 全App MUST 最小字号18sp，正文22sp+，按钮触控区 ≥ 48x48dp
- **FR-009**: 系统 MUST 不显示红色错误标记或负面分数，使用暖色调（鹦鹉绿#1A8A7D + 暖橙#F5A623）
- **FR-010**: 子女 MUST 能通过3步设置流（注册→填信息→生成二维码）为父母创建账号，全程 ≤ 3分钟
- **FR-011**: 父母 MUST 能通过扫描二维码自动登录，无需自行注册或输入密码
- **FR-012**: 子女仪表盘 MUST 显示父母学习数据（对话次数、时长、新词数、连续天数），支持一键分享
- **FR-013**: 系统 MUST 在每次对话结束后自动生成复习卡片（英文+中文+音标+中文谐音+可听发音）
- **FR-014**: 鹦鹉 MUST 有7个动画状态（睡觉/醒来/教学/开心/鼓励/思考/再见），随对话自动切换
- **FR-015**: 系统 MUST 实现改良SM-2间隔重复算法，在新场景中自然复现需要复习的旧词汇
- **FR-016**: 鹦鹉 MUST 有6级成长系统，由学习行为驱动XP积累
- **FR-017**: 系统 MUST 每天最多发送1条个性化推送邀请用户聊天，内容包含昨天学习的内容
- **FR-018**: 发音评估 MUST 使用"可理解度"（comprehensibility）标准，而非"标准度"（native-likeness）
- **FR-019**: 系统 MUST 支持离线浏览复习卡片（本地缓存）
- **FR-020**: ASR/LLM/TTS MUST 通过接口抽象层封装，支持运行时或部署时切换供应商

### Key Entities

- **User（用户）**: 分为elder（老人）和child（子女）两种角色，包含个人信息、学习统计、订阅状态
- **Family（家庭关系）**: 子女与老人的绑定关系
- **Session（对话会话）**: 一次语音对话的完整记录，关联场景、学习成果、XP
- **Scene（场景）**: 教学场景配置，包含核心短语、Prompt模板、难度等级
- **VocabItem（词汇）**: 用户已学词汇及SRS状态（等级、下次复习日期、正确/错误次数）
- **ReviewCard（复习卡片）**: 每次对话后生成的卡片，包含短语列表和分享图片URL
- **PetStatus（鹦鹉状态）**: 叽叽的XP、成长阶段、里程碑记录
- **Subscription（订阅）**: 用户订阅信息，支持子女代付

## Success Criteria

### Measurable Outcomes

- **SC-001**: 55-70岁用户在无人指导下，3次点击内可从打开App到开始语音对话
- **SC-002**: 语音对话端到端延迟（用户说完到听到回复）< 2秒
- **SC-003**: 首页加载时间 < 1秒
- **SC-004**: D1留存率（第2天再次打开）≥ 40%
- **SC-005**: D7留存率（注册7天后仍活跃）≥ 25%
